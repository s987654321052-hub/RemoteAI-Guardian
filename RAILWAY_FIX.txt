🚀 部署步驟:

1️⃣ 提交到 Git
   git add .
   git commit -m "修復 Railway 部署配置"
   git push origin main

2️⃣ 在 Railway 儀表板中重新部署
   • 登入 Railway: https://railway.app
   • 進入你的 RemoteAI-Guardian 項目
   • 點擊 "Deploy" 或讓它自動重新部署
   • 等待部署完成（通常 2-3 分鐘）

3️⃣ 驗證部署
   部署完成後，查看：
   • ✅ Logs 選項卡中沒有 ENOENT 錯誤
   • ✅ 應用顯示為 "Running"（綠色指示燈）
   • ✅ 公網 URL 可訪問

📍 測試你的部署:

🔧 文件改動說明:

1. railway-start.js (新建)
   • 簡化版啟動腳本
   • 只在單個進程中運行（不使用 child_process）
   • 包含認證系統和 LINE Webhook 所有功能
   • 自動監聽 PORT 環境變數（Railway 提供）

2. Procfile (已更新)
   • 舊: web: cd auth-system && npm start
   • 新: web: node railway-start.js
   • 直接指向新的啟動腳本

3. Dockerfile (已更新)
   • 端口改為 3000（Railway 標準）
   • 不再指向 start.js
   • 健康檢查現在檢查 /health

═══════════════════════════════════════════════════════════════════

⚙️ Railway 環境變數配置:

確保在 Railway 儀表板中設置了這些變數:

必需:
   • NODE_ENV=production
   • PORT=3000

可選（LINE 通知）:
   • LINE_ACCESS_TOKEN=你的令牌
   • LINE_USER_ID=你的用戶ID
   • LINE_CHANNEL_ID=你的頻道ID
   • LINE_CHANNEL_SECRET=你的密鑰

🔍 故障排除:

問題 1: 部署後仍顯示 ENOENT 錯誤
解決方案:
   • 確保提交了所有新文件到 Git
   • 在 Railway 儀表板中點擊 "Redeploy"
   • 檢查 Logs 確保 railway-start.js 在運行

問題 2: 應用啟動後立即崩潰
解決方案:
   • 查看 Railway Logs
   • 確保 package.json 中有所有必需的依賴
   • 檢查 .env 變數是否正確設置

問題 3: LINE 通知不工作
解決方案:
   • 確認 LINE_ACCESS_TOKEN 正確
   • 確認 LINE_USER_ID 正確
   • Railway Logs 中應該看到 "LINE 通知已發送"
